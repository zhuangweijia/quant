# 交易模块（Trading）需求文档

> 版本：v1.0  
> 日期：2026-05-13  
> 前置模块：用户管理、行情、策略、风控

---

## 1. 模块概述

交易模块是 QuantPlatform 的核心执行层，负责将用户的交易意图（手动下单或策略信号）转化为实际的订单提交、状态跟踪、持仓管理和账户管理。支持模拟盘和实盘两种交易模式，通过 BrokerAdapter 抽象层对接不同交易所（Alpaca / Binance / 模拟撮合），并依赖风控模块进行下单前拦截。

## 4. 订单状态流转

```
                    ┌─────────────┐
                    │   pending    │  (创建成功)
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │  submitted   │  (已提交到交易所)
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
       ┌──────▼──────┐    │     ┌──────▼──────┐
       │  rejected   │    │     │partial_filled│
       └─────────────┘    │     └──────┬───────┘
                          │            │
                   ┌──────▼──────┐    │
                   │  cancelled  │◄───┘
                   └─────────────┘
                          │
                   ┌──────▼──────┐
                   │   filled    │  (完全成交)
                   └─────────────┘
                          │
                   ┌──────▼──────┐
                   │   expired   │  (超时未成交)
                   └─────────────┘
```

| 转换 | 触发条件 |
|------|----------|
| pending → submitted | 订单成功提交到交易所，获得 broker_order_id |
| pending → cancelled | 用户撤单或系统撤销 |
| submitted → filled | 订单完全成交 |
| submitted → partial_filled | 订单部分成交 |
| submitted → rejected | 交易所拒绝（余额不足、标的停牌等） |
| submitted → cancelled | 用户撤单 |
| submitted → expired | 超过 order_timeout（默认30秒）未成交 |
| partial_filled → filled | 剩余部分成交 |
| partial_filled → cancelled | 用户撤销未成交部分 |

## 5. 下单流程

### 5.1 手动下单流程

```
用户填写下单表单
       │
       ▼
  前端表单校验（必填、数量、价格）
       │
       ▼
  二次确认弹窗（订单摘要）
       │
       ▼
  POST /api/v1/trade/order
       │
       ▼
  后端参数校验（数量精度、市场交易时段）
       │
       ▼
  风控引擎检查（FR-6.2 下单前风控检查）
       │
     通过？
    /    \
  是      否 → 返回 400 + 拦截原因
   │
   ▼
  创建 Order 记录（status=pending）
       │
       ▼
  BrokerAdapter.submit_order()
       │
     成功？
    /    \
  是      否 → status=rejected, 返回错误
   │
   ▼
  status=submitted, 保存 broker_order_id
       │
       ▼
  启动状态轮询 / WebSocket 监听
       │
       ▼
  成交 → status=filled → 更新 Position
       │
       ▼
  WebSocket 推送 trade:order + trade:position
```

### 5.2 策略自动下单流程

| 步骤 | 说明 |
|------|------|
| 1 | 策略引擎执行 `on_bar()` / `on_tick()` 回调 |
| 2 | 策略调用 `self.buy()` / `self.sell()` |
| 3 | 交易信号进入 OrderManager，关联 strategy_id |
| 4 | 后续流程与手动下单一致（风控→下单→状态跟踪） |
| 5 | 订单状态变更写入策略日志 |

## 6. 持仓管理规则

### 6.1 持仓更新时机

| 事件 | 操作 |
|------|------|
| 买单完全成交 | 新增持仓或增加数量，更新均价（加权平均） |
| 卖单完全成交 | 减少持仓数量，数量为零时删除持仓记录 |
| 部分成交 | 按已成交数量更新持仓 |
| 现价变动 | 通过行情 Tick 更新浮动盈亏（仅前端计算，不写库） |

### 6.2 均价计算

```
新均价 = (原均价 × 原数量 + 成交价 × 成交数量) / (原数量 + 成交数量)
```

### 6.3 各市场持仓规则

| 市场 | 规则 |
|------|------|
| A股 | 买入数量必须为 100 的整数倍（1手=100股）；不允许卖空（卖出数量≤持仓数量） |
| 美股 | 数量可以为任意正整数；不允许卖空（MVP 阶段） |
| 加密货币 | 数量精度由交易所规则决定（如 BTC 精度 8 位）；不允许卖空 |

## 7. 交易模式

### 7.1 模拟盘（Paper Trading）

| 项目 | 说明 |
|------|------|
| Broker | PaperBroker（本地模拟撮合） |
| 初始资金 | ¥1,000,000（可在设置页调整） |
| 撮合价格 | 市价单取最新 Tick 价 ± 滑点；限价单检查 Tick 是否触及 |
| 手续费 | 按市场标准费率计算（与回测一致） |
| 订单超时 | 限价单默认 30 秒后过期 |
| 数据存储 | orders/positions 表 market_type=paper |
| 切换 | 设置页切换，需二次确认 |

### 7.2 实盘（Live Trading）

| 项目 | 说明 |
|------|------|
| Broker | AlpacaBroker（美股）/ BinanceBroker（加密货币） |
| 资金 | 使用交易所真实账户余额 |
| 订单 | 直接提交到交易所，通过轮询/WebSocket 同步状态 |
| 风控 | 同模拟盘，必须经过完整风控检查 |
| 切换 | 从模拟切换到实盘需输入密码二次确认 |
| 安全 | API Key 加密存储（AES-256），前端只显示前4后4位 |

### 7.3 模式切换规则

| 规则 | 说明 |
|------|------|
| 默认模式 | 新用户默认模拟盘 |
| 切换确认 | 切换到实盘需输入登录密码验证 |
| 策略处理 | 切换时自动停止所有运行中的策略 |
| 持仓保留 | 模拟盘持仓和实盘持仓独立，切换不影响 |
| 权限要求 | viewer 角色无法切换模式 |

## 10. 后端服务架构

### 10.1 BrokerAdapter 抽象层

```
BrokerAdapter (ABC)
├── PaperBroker       # 模拟盘撮合
├── AlpacaBroker      # 美股 Alpaca
└── BinanceBroker     # 加密货币 Binance
```

| 方法 | 说明 |
|------|------|
| submit_order() | 提交订单，返回 broker_order_id |
| cancel_order() | 撤销订单 |
| get_order_status() | 查询订单状态 |
| get_positions() | 查询交易所持仓 |
| get_account() | 查询账户信息 |
| health_check() | 检查连接状态 |

### 10.2 OrderManager

| 职责 | 说明 |
|------|------|
| 订单提交 | 校验→风控→创建记录→调用Broker→启动轮询 |
| 订单撤销 | 调用Broker撤单→更新状态→推送事件 |
| 状态轮询 | 每秒轮询交易所状态，最长10分钟 |
| 事件发布 | 状态变更时通过 event_bus 发布 trade:order |
| 持仓更新 | 订单成交后自动更新 Position 表 |
| 超时处理 | 超过 order_timeout 的限价单自动过期 |

### 10.3 PaperBroker 模拟撮合

| 规则 | 说明 |
|------|------|
| 市价单 | 以最新 Tick 价格 ± 滑点（默认 0.1%）成交 |
| 限价买单 | Tick 价格 ≤ 限价时以限价成交 |
| 限价卖单 | Tick 价格 ≥ 限价时以限价成交 |
| 止损单 | Tick 触及止损价时以止损价 ± 滑点成交 |
| 延迟模拟 | 默认 100ms 延迟模拟网络延迟 |
| 余额检查 | 买入时检查可用资金是否充足 |

## 11. 交易时段校验

| 市场 | 交易时段（北京时间） | 说明 |
|------|---------------------|------|
| A股 | 09:30-11:30, 13:00-15:00 | 法定工作日，节假日休市 |
| 美股 | 21:30-04:00（夏令时 21:30-03:00） | 含盘前盘后可选 |
| 加密货币 | 24/7 | 全天候交易 |

**校验规则：**
- 非交易时段提交订单返回 400 错误，提示"市场未开盘"
- 加密货币市场跳过时段校验
- A股节假日需维护交易日历（后续接入）

## 12. 业务规则

| 规则 | 说明 |
|------|------|
| 卖出校验 | 卖出数量不得超过可用持仓（qty - frozen_qty） |
| A股手数 | A股买入数量必须为 100 的整数倍 |
| 余额校验 | 买入金额 + 手续费 ≤ 可用余额 |
| 风控前置 | 所有订单（手动/策略）必须经过风控检查 |
| 策略关联 | 策略下单自动关联 strategy_id，手动下单为 null |
| 订单不可修改 | 已提交的订单不可修改，只能撤单重下 |
| 并发控制 | 同一用户同一标的同时只允许一个挂单（pending/submitted） |
| 日切重置 | 每日 00:00 重置日盈亏计算和日交易次数计数 |
| 数据隔离 | 所有查询附加 WHERE user_id = ? |
| viewer 禁止 | viewer 角色不允许下单和撤单操作 |

## 14. 错误处理

| 错误码 | HTTP | 场景 | 提示信息 |
|--------|------|------|----------|
| MARKET_CLOSED | 400 | 非交易时段下单 | "{market} 市场当前不在交易时段" |
| INSUFFICIENT_BALANCE | 400 | 余额不足 | "可用余额不足，需要 {amount}，可用 {balance}" |
| INSUFFICIENT_POSITION | 400 | 持仓不足 | "持仓不足，可用 {available}，需要 {required}" |

## 15. 非功能需求

| 编号 | 需求 | 指标 |
|------|------|------|
| T-NFR-01 | 下单响应 | 从 API 接收到订单创建 < 500ms |

| T-NFR-03 | 持仓刷新 | 现价变动到浮动盈亏更新 < 1s |

| T-NFR-07 | 事务安全 | 下单+持仓更新在同一数据库事务中 |
