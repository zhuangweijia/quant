# 风控模块（Risk Management）需求文档

> 版本：v1.0  
> 日期：2026-05-13  
> 前置模块：用户管理、交易

---

## 1. 模块概述

风控模块为 QuantPlatform 提供事前拦截和事中监控两层防护。事前拦截在下单前检查所有启用的风控规则，拒绝违规订单；事中监控实时追踪持仓盈亏和日累计亏损，触发止损止盈或熔断机制时自动平仓并停止交易。同时通过多渠道（站内、邮件、Webhook）向用户发送告警通知。

## 4. 风控规则类型

### 4.1 规则一览

| 编号 | 规则类型 | rule_type | 说明 | 参数 |
|------|----------|-----------|------|------|
| RT-01 | 单标的最大持仓金额 | `max_position_value` | 限制单只标的的持仓总市值 | `max_value` (float) |
| RT-02 | 单标的最大仓位占比 | `max_position_ratio` | 限制单只标的占总资产比例 | `max_ratio` (float, 0-1) |
| RT-03 | 总仓位上限 | `max_total_position` | 限制总持仓占总资产比例 | `max_ratio` (float, 0-1) |
| RT-04 | 单笔止损 | `stop_loss` | 持仓浮亏达到阈值自动平仓 | `stop_loss_pct` (float, 0-1) |
| RT-05 | 单笔止盈 | `take_profit` | 持仓浮盈达到阈值自动平仓 | `take_profit_pct` (float, 0-1) |
| RT-06 | 日亏损限额 | `daily_loss_limit` | 当日累计亏损达到限额停止所有交易 | `max_daily_loss` (float) |
| RT-07 | 日交易次数上限 | `daily_trade_limit` | 当日交易次数达到上限拒绝新订单 | `max_trades` (int) |
| RT-08 | 交易黑名单 | `blacklist` | 禁止交易指定标的 | `symbols` (list[str]) |
| RT-09 | 单笔最大下单金额 | `max_order_amount` | 限制单笔订单金额 | `max_amount` (float) |

### 4.2 各规则详细说明

#### RT-01 单标的最大持仓金额

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查（仅买单） |
| 检查逻辑 | 当前持仓市值 + 新订单金额 > max_value → 拦截 |
| 适用范围 | 全局或策略级 |
| 参数示例 | `{"max_value": 100000}` — 单标的最多持仓 10 万元 |

#### RT-02 单标的最大仓位占比

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查（仅买单） |
| 检查逻辑 | (当前持仓市值 + 新订单金额) / 总资产 > max_ratio → 拦截 |
| 适用范围 | 全局或策略级 |
| 参数示例 | `{"max_ratio": 0.3}` — 单标的不超过总资产 30% |

#### RT-03 总仓位上限

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查（仅买单） |
| 检查逻辑 | (当前总持仓市值 + 新订单金额) / 总资产 > max_ratio → 拦截 |
| 适用范围 | 仅全局 |
| 参数示例 | `{"max_ratio": 0.8}` — 总仓位不超过总资产 80% |

#### RT-04 单笔止损

| 项目 | 说明 |
|------|------|
| 触发时机 | 事中监控（行情 Tick 更新时） |
| 检查逻辑 | (现价 - 均价) / 均价 ≤ -stop_loss_pct → 自动平仓 |
| 动作 | 以市价卖出全部持仓 + 发送 error 级告警 |
| 适用范围 | 策略级（绑定具体策略或具体标的） |
| 参数示例 | `{"stop_loss_pct": 0.1}` — 亏损 10% 自动止损 |

#### RT-05 单笔止盈

| 项目 | 说明 |
|------|------|
| 触发时机 | 事中监控（行情 Tick 更新时） |
| 检查逻辑 | (现价 - 均价) / 均价 ≥ take_profit_pct → 自动平仓 |
| 动作 | 以市价卖出全部持仓 + 发送 warning 级告警 |
| 适用范围 | 策略级 |
| 参数示例 | `{"take_profit_pct": 0.3}` — 盈利 30% 自动止盈 |

#### RT-06 日亏损限额

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查 + 平仓后累计 |
| 检查逻辑 | 当日已实现亏损 + 浮亏 > max_daily_loss → 拦截新单 |
| 熔断动作 | 停止所有运行策略 + 拒绝所有新单 + 发送 error 告警 |
| 恢复方式 | 次日自动恢复，或管理员手动恢复 |
| 适用范围 | 仅全局 |
| 参数示例 | `{"max_daily_loss": 50000}` — 日亏损不超过 5 万元 |

#### RT-07 日交易次数上限

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查 |
| 检查逻辑 | 当日已成交订单数 ≥ max_trades → 拦截 |
| 计数方式 | 按 filled 状态的订单计数（含部分成交） |
| 适用范围 | 全局或策略级 |
| 参数示例 | `{"max_trades": 50}` — 每日最多交易 50 次 |

#### RT-08 交易黑名单

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查 |
| 检查逻辑 | order.symbol in symbols → 拦截 |
| 适用范围 | 全局或策略级 |
| 参数示例 | `{"symbols": ["MSTR", "SHIBUSDT"]}` |

#### RT-09 单笔最大下单金额

| 项目 | 说明 |
|------|------|
| 触发时机 | 下单前检查 |
| 检查逻辑 | 数量 × 价格 > max_amount → 拦截（市价单用最新价） |
| 适用范围 | 全局或策略级 |
| 参数示例 | `{"max_amount": 100000}` — 单笔最多 10 万元 |

## 5. 风控引擎架构

### 5.1 规则执行流程

```
订单提交
    │
    ▼
加载风控规则
(全局规则 + 策略规则，按 priority 升序)
    │
    ▼
构建上下文 context
(总资产、持仓市值、日亏损、日交易次数、当前价格...)
    │
    ▼
逐条执行规则
    │
    ┌──────────────┐
    │ 规则 1 通过？ │──── 否 → 拦截，返回原因
    └──────┬───────┘
           │ 是
    ┌──────▼───────┐
    │ 规则 2 通过？ │──── 否 → 拦截，返回原因
    └──────┬───────┘
           │ 是
          ...
           │
    ┌──────▼───────┐
    │ 规则 N 通过？ │──── 否 → 拦截，返回原因
    └──────┬───────┘
           │ 是
           ▼
    下单放行
```

### 5.2 事中监控流程

```
行情 Tick 到达
    │
    ▼
遍历所有持仓
    │
    ▼
计算浮动盈亏 = (现价 - 均价) / 均价
    │
    ▼
检查止损/止盈规则
    │
    ├── 触发止损 → 市价卖出 + error 告警
    ├── 触发止盈 → 市价卖出 + warning 告警
    └── 未触发 → 更新前端浮动盈亏
    │
    ▼
检查日亏损限额
    │
    └── 达到限额 → 熔断（停止策略 + 拒绝新单 + error 告警）
```

### 5.3 上下文数据（context）

| 字段 | 来源 | 说明 |
|------|------|------|
| total_equity | account 表 | 总资产（现金+市值） |
| cash | account 表 | 可用现金 |
| total_position_value | 聚合 positions 表 | 总持仓市值 |
| position_values | 聚合 positions 表 | 各标的持仓市值 {symbol: value} |
| current_price | market_data 缓存 | 订单标的的当前价格 |
| daily_loss | Redis `risk:daily:{user_id}` | 当日已实现亏损 |
| daily_trades | Redis `risk:daily:{user_id}` | 当日已成交次数 |
| positions | positions 表 | 用户当前持仓列表 |

## 7. 告警通知

### 7.1 通知渠道

| 渠道 | 配置 | 说明 |
|------|------|------|
| 站内通知 | 默认开启 | WebSocket 推送到前端，持久化到 alerts 表 |
| 邮件通知 | 需配置 SMTP | 发送到用户邮箱（可选） |
| Webhook | 需配置 URL | POST JSON 到用户配置的 URL（可选） |

### 7.2 告警级别

| 级别 | 颜色 | 场景 |
|------|------|------|
| info | 蓝色 | 策略启动/停止、规则启用/禁用 |
| warning | 橙色 | 接近止损线（如浮亏达止损的80%）、规则被编辑 |
| error | 红色 | 触发止损/止盈、达到日亏损限额、风控拦截订单 |

### 7.3 告警数据格式

```json
{
  "id": "uuid",
  "level": "error",
  "title": "止损触发",
  "message": "BTCUSDT 浮亏达 -10.5%，触发止损规则，已自动平仓",
  "strategy_id": "uuid",
  "created_at": "2026-05-13T10:30:00Z"
}
```

### 7.4 WebSocket 推送

| 主题 | 数据 | 说明 |
|------|------|------|
| `risk:alert` | Alert 完整数据 | 新告警实时推送 |
| `risk:blocked` | `{order_id, rule_type, reason}` | 订单被拦截推送 |

## 10. Redis 缓存设计

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `risk:daily:{user_id}` | Hash | 24h | 日风控计数器 |
| `risk:daily:{user_id}:loss` | Field | - | 当日已实现亏损（float） |
| `risk:daily:{user_id}:trades` | Field | - | 当日已成交次数（int） |
| `risk:daily:{user_id}:blocked` | Field | - | 当日被拦截次数（int） |
| `risk:circuit_breaker:{user_id}` | String | 至当日 23:59:59 | 熔断标记（值为 "daily_loss_limit"） |

### 10.1 日计数器重置

| 方式 | 说明 |
|------|------|
| TTL 自动过期 | Key 设置 TTL 到当日 23:59:59，次日自动清除 |
| 定时任务 | 每日 00:00 扫描所有 `risk:daily:*` Key，验证/清理 |
| 手动恢复 | 管理员 API 清除用户的熔断标记 |

## 11. 业务规则

| 规则 | 说明 |
|------|------|
| 规则执行顺序 | 先全局规则后策略规则，同范围内按 priority 升序 |
| 规则互不覆盖 | 所有启用的规则独立检查，任一不通过即拦截 |
| 规则数量限制 | 每个策略最多 20 条规则，全局最多 30 条规则 |
| 止损不可跳过 | 自动止损订单不经过风控检查，直接提交 |
| 止盈不可跳过 | 自动止盈订单同止损逻辑 |
| 熔断后状态 | 触发日亏损限额后所有策略强制停止，已有挂单撤销 |
| 熔断恢复 | 次日自动恢复，或管理员通过 API 手动恢复 |
| 规则即时生效 | 新增/修改/启用规则后立即生效，无需重启 |
| 规则删除保护 | 删除规则需二次确认弹窗 |
| 告警持久化 | 所有告警写入 alerts 表，前端离线时不丢失 |
| 告警保留期 | 90 天自动清理，保留期间可随时查看 |
| 数据隔离 | 所有查询附加 WHERE user_id = ? |

## 13. 错误处理

|--------|------|------|----------|
