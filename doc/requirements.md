## 1. 引言

### 1.1 编写目的

本文档定义 QuantPlatform 量化交易系统的完整需求，作为系统设计、开发、测试的基准参考。面向开发团队、产品负责人和技术评审人员。

### 1.2 项目背景

当前量化交易者面临以下痛点：

- 多市场操作需要切换不同的工具和平台
- 策略开发、回测、实盘交易流程割裂
- 缺乏统一的风控管理和策略监控手段
- 自建系统从零开始工作量巨大

QuantPlatform 旨在提供一套开箱即用的全流程量化交易解决方案，覆盖从数据采集、策略开发、回测验证到实盘交易的完整链路。

## 2. 总体描述

### 2.1 产品视角

QuantPlatform 是一个独立运行的 Web 应用系统，采用前后端分离架构：

```
┌───────────────────────────────────────────────────────────┐
│                      用户浏览器                            │
│                 Vue3 SPA (Element Plus)                    │
└───────────────────────────┬───────────────────────────────┘
                            │ HTTPS / WSS
┌───────────────────────────┴───────────────────────────────┐
│                     Nginx 反向代理                          │
│               (SSL 终结 / 静态资源 / 负载均衡)               │
└───────────┬───────────────────────────────────┬───────────┘
            │                                   │
┌───────────┴───────────┐           ┌───────────┴───────────┐
│   FastAPI 后端服务      │           │    数据存储层           │
│  ┌─────────────────┐  │           │  ┌─────────────────┐  │
│  │ REST API        │  │           │  │ PostgreSQL 16   │  │
│  │ WebSocket       │  │◄─────────►│  │ (业务+时序数据)  │  │
│  │ 后台任务        │  │           │  ├─────────────────┤  │
│  │ 策略引擎        │  │           │  │ Redis 7         │  │
│  │ 交易引擎        │  │           │  │ (缓存+PubSub)   │  │
│  └─────────────────┘  │           │  └─────────────────┘  │
└───────────────────────┘           └───────────────────────┘
            │
            │ 外部接口
┌───────────┴───────────────────────────────────────────────┐
│                     外部数据源 / 券商                        │
│  AKShare │ Alpaca API │ Binance API │ XtQuant │ ...       │
└───────────────────────────────────────────────────────────┘
```

### 2.2 系统目标

| 目标 | 度量标准 |
|------|----------|
| 支持多市场 | 同时接入 A股、美股、加密货币 ≥ 3 个市场 |
| 低延迟行情 | 行情数据从采集到前端展示延迟 < 2 秒 |
| 回测效率 | 1 年日K线级别回测完成时间 < 30 秒 |
| 系统可用性 | 交易时段系统可用率 > 99.5% |
| 并发策略 | 同时运行 ≥ 5 个策略实例 |
| 数据容量 | 支持存储 ≥ 5 年历史K线数据 |

### 2.3 运行环境

| 环境 | 配置要求 |
|------|----------|
| 开发环境 | macOS / Linux，Docker Desktop，16GB RAM |
| 生产环境（单机） | Ubuntu 22.04+，4核 CPU，16GB RAM，500GB SSD |
| 浏览器 | Chrome 100+、Firefox 100+、Edge 100+ |

## 4. 功能需求

### 4.1 用户管理模块

#### FR-1.1 用户注册

- **描述**: 新用户通过注册页面创建账号
- **前置条件**: 无
- **输入**: 用户名（3-32字符，字母数字下划线）、密码（8-64字符，需包含字母和数字）、确认密码
- **处理逻辑**:
  1. 校验用户名唯一性
  2. 校验密码复杂度
  3. 使用 bcrypt 哈希密码（cost factor ≥ 12）
  4. 创建用户记录，默认角色为 `trader`
- **输出**: 注册成功 / 具体错误信息
- **业务规则**:
  - 用户名不可重复
  - 密码不得与用户名相同
  - 首个注册用户自动设为 `admin`

#### FR-1.2 用户登录

- **描述**: 已注册用户通过用户名和密码登录系统
- **输入**: 用户名、密码
- **处理逻辑**:
  1. 查询用户记录
  2. 验证密码哈希
  3. 生成 JWT Access Token（有效期 30 分钟）和 Refresh Token（有效期 7 天）
  4. 记录登录时间
- **输出**: Access Token + Refresh Token
- **业务规则**:
  - 连续 5 次登录失败后锁定账号 15 分钟
  - Token 使用 RS256 算法签名

#### FR-1.3 Token 刷新

- **描述**: 当 Access Token 过期时，使用 Refresh Token 获取新的 Access Token
- **输入**: Refresh Token
- **处理逻辑**: 验证 Refresh Token 有效性和签名，签发新的 Access Token
- **输出**: 新的 Access Token

#### FR-1.4 修改密码

- **描述**: 用户修改自己的登录密码
- **输入**: 旧密码、新密码、确认新密码
- **处理逻辑**: 验证旧密码 → 校验新密码复杂度 → 更新密码哈希
- **业务规则**: 修改密码后，该用户其他设备的 Token 立即失效

### 4.2 行情数据模块

#### FR-2.1 市场标的搜索

- **描述**: 用户通过关键词搜索可交易的标的
- **输入**: 关键词（股票代码或名称）、市场筛选条件（可选）
- **输出**: 匹配的标的列表（代码、名称、市场、当前价格）
- **业务规则**:
  - A股：支持股票代码（如 600519）和名称（如 贵州茅台）搜索
  - 美股：支持股票代码（如 AAPL）和公司名搜索
  - 加密货币：支持交易对搜索（如 BTCUSDT）

#### FR-2.2 历史K线数据查询

- **描述**: 获取指定标的的历史K线（OHLCV）数据
- **输入**:
  - `symbol`: 标的代码（必填）
  - `market`: 市场（必填，a_stock / us_stock / crypto）
  - `timeframe`: K线周期（必填，1m / 5m / 15m / 30m / 1h / 4h / 1d / 1w）
  - `start`: 起始时间（可选，默认为最近 500 根K线）
  - `end`: 结束时间（可选，默认为当前时间）
  - `limit`: 返回数量限制（可选，默认 500，最大 5000）
- **输出**: K线数据数组，每条包含 `{ timestamp, open, high, low, close, volume }`
- **业务规则**:
  - 优先从本地数据库读取
  - 本地缺失时从数据源实时拉取并缓存
  - K线数据按时间升序排列

#### FR-2.3 实时行情推送

- **描述**: 通过 WebSocket 向前端实时推送行情数据
- **输入**: WebSocket 连接，订阅标的列表
- **输出**: 推送 Tick 级别或 K线级别的实时数据
- **业务规则**:
  - 支持订阅多个标的
  - 推送频率：A股约 3 秒一次（免费数据源限制）、美股约 1 秒、加密货币实时
  - 连接断开后自动重连
  - 单个连接最多订阅 50 个标的

#### FR-2.4 数据采集定时任务

- **描述**: 后台定时采集各市场行情数据并存入数据库
- **处理逻辑**:
  - A股：交易日每 5 分钟采集一次实时K线，每日收盘后采集完整日K线
  - 美股：美东时间 09:30-16:00 每 1 分钟采集，盘后采集日K线
  - 加密货币：7x24 每分钟采集
- **业务规则**:
  - 采集失败时自动重试 3 次，间隔 10 秒
  - 重复数据以 `(symbol, market, timeframe, timestamp)` 去重
  - 数据采集状态记录到日志

#### FR-2.5 数据源管理

- **描述**: 管理各市场的数据源配置
- **输入**: 数据源类型、API Key/Secret、请求频率限制
- **输出**: 数据源连接状态、剩余配额
- **业务规则**:
  - 支持配置多个数据源作为备份
  - 主数据源失败时自动切换到备用数据源
  - API Key 加密存储

### 4.3 策略管理模块

#### FR-3.1 创建策略

- **描述**: 用户通过 Web 界面创建新的交易策略
- **输入**:
  - `name`: 策略名称（必填，2-128 字符）
  - `market`: 目标市场（必填）
  - `code`: 策略 Python 代码（必填，继承 BaseStrategy）
  - `params`: 策略参数（JSON 格式，可选）
  - `description`: 策略描述（可选）
- **处理逻辑**:
  1. 校验代码语法正确性（AST 解析）
  2. 校验代码包含继承自 BaseStrategy 的类
  3. 校验策略参数与代码中的参数声明匹配
  4. 保存策略记录，状态设为 `draft`
- **输出**: 创建成功的策略详情
- **业务规则**:
  - 每个用户最多创建 50 个策略
  - 策略代码大小不超过 100KB
  - 策略代码中的 `import` 仅允许白名单模块（pandas, numpy, talib, datetime, math 及标准库）

#### FR-3.2 编辑策略

- **描述**: 修改已有策略的代码或参数
- **前置条件**: 策略状态为 `draft` 或 `stopped`
- **输入**: 策略 ID + 修改内容
- **业务规则**:
  - `running` 状态的策略必须先停止才能编辑
  - 编辑后策略状态重置为 `draft`

#### FR-3.3 删除策略

- **描述**: 删除一个策略
- **前置条件**: 策略状态为 `draft` 或 `stopped`
- **业务规则**:
  - `running` 状态的策略必须先停止才能删除
  - 删除策略不删除关联的回测结果和历史订单记录
  - 软删除（标记 deleted_at），保留数据

#### FR-3.4 策略列表

- **描述**: 分页展示用户的所有策略
- **输入**: 页码、每页数量、状态筛选、市场筛选、关键词搜索
- **输出**: 策略列表（名称、市场、状态、创建时间、最近运行时间）
- **业务规则**: 默认按更新时间倒序排列

#### FR-3.5 启动策略

- **描述**: 启动一个策略进入运行状态
- **前置条件**: 策略状态为 `draft` 或 `stopped`
- **处理逻辑**:
  1. 验证策略代码可正常加载
  2. 初始化策略实例（调用 `on_init`）
  3. 注册行情数据订阅
  4. 将策略状态设为 `running`
  5. 启动策略调度任务
- **业务规则**:
  - 单用户同时运行策略数上限为 10 个（可配置）
  - 启动失败时回滚状态并返回错误信息

#### FR-3.6 停止策略

- **描述**: 停止一个正在运行的策略
- **前置条件**: 策略状态为 `running`
- **处理逻辑**:
  1. 调用策略的 `on_stop` 回调
  2. 取消行情订阅
  3. 将策略状态设为 `stopped`
  4. 可选：停止时自动平仓（用户可配置）
- **业务规则**:
  - 停止操作不可逆，需要重新启动
  - 停止时如有未成交订单，等待成交或超时（30秒）后撤单

#### FR-3.7 策略日志查看

- **描述**: 查看策略运行时产生的日志
- **输入**: 策略 ID、日志级别筛选、时间范围、关键词搜索
- **输出**: 日志列表（时间戳、级别、消息内容）
- **业务规则**: 日志保留最近 30 天

### 4.4 回测引擎模块

#### FR-4.1 配置回测参数

- **描述**: 用户设置回测的参数和范围
- **输入**:
  - `strategy_id`: 要回测的策略 ID
  - `symbol`: 标的代码或标的列表
  - `start_date`: 回测起始日期（必填）
  - `end_date`: 回测结束日期（必填）
  - `timeframe`: K线周期（必填）
  - `initial_capital`: 初始资金（必填，默认 1,000,000）
  - `commission_rate`: 手续费率（可选，默认各市场标准费率）
  - `slippage`: 滑点模型（可选，默认固定滑点 0.1%）
  - `params`: 策略参数覆盖（可选）
- **业务规则**:
  - 起始日期不得晚于结束日期
  - 回测区间最长 5 年
  - 初始资金范围：1,000 ~ 100,000,000

#### FR-4.2 执行回测

- **描述**: 运行策略回测并生成结果
- **处理逻辑**:
  1. 从数据库加载指定范围的历史K线数据
  2. 校验数据完整性，缺失超过 10% 则拒绝执行
  3. 初始化回测引擎和模拟账户
  4. 逐根K线喂入策略实例的 `on_bar` 回调
  5. 策略产生的交易信号进入模拟撮合引擎
  6. 模拟撮合引擎计算成交价（考虑滑点和手续费）
  7. 更新模拟持仓和账户余额
  8. 回测完成后计算统计指标
  9. 保存回测结果到数据库
- **业务规则**:
  - 回测异步执行，通过 WebSocket 通知进度
  - 回测超时时间 10 分钟
  - 同一用户同时最多执行 3 个回测任务

#### FR-4.3 回测撮合规则

- **描述**: 回测引擎中模拟订单撮合的规则
- **处理逻辑**:
  - **市价单**: 以下一根K线的开盘价成交
  - **限价单**:
    - 买入: 当K线最低价 ≤ 限价时，以限价成交
    - 卖出: 当K线最高价 ≥ 限价时，以限价成交
  - **止损单**: 当K线触及止损价时，以止损价成交
  - **成交量限制**: 单笔成交量不超过该K线成交量的 25%
- **手续费计算**:
  - A股: 买入 0.025%（佣金）+ 0.01%（过户费），卖出额外加 0.1%（印花税）
  - 美股: 每股 $0.005（最低 $1）
  - 加密货币: 0.1%（Maker）/ 0.1%（Taker）

#### FR-4.4 回测统计指标

- **描述**: 回测完成后计算的统计指标
- **输出指标列表**:

| 指标 | 计算方式 |
|------|----------|
| 总收益率 | (期末权益 - 初始资金) / 初始资金 × 100% |
| 年化收益率 | 总收益率按年化复利折算 |
| 夏普比率 | (日均收益率 - 无风险利率) / 日收益率标准差 × √252 |
| 索提诺比率 | (日均收益率 - 无风险利率) / 下行标准差 × √252 |
| 最大回撤 | 峰值到谷底的最大跌幅百分比 |
| 最大回撤持续期 | 从回撤开始到恢复到前高的天数 |
| 胜率 | 盈利交易次数 / 总交易次数 × 100% |
| 盈亏比 | 平均盈利 / 平均亏损 |
| 总交易次数 | 开仓到平仓的完整交易次数 |
| 日均交易次数 | 总交易次数 / 回测交易日数 |
| 平均持仓周期 | 所有交易持仓时间的平均值 |
| Calmar 比率 | 年化收益率 / 最大回撤 |

#### FR-4.5 回测结果查看

- **描述**: 查看回测的详细结果和可视化
- **输出**:
  - 权益曲线图（对比基准收益）
  - 回撤曲线图
  - 每笔交易明细（买卖时间、价格、数量、盈亏）
  - 月度收益热力图
  - 统计指标摘要表
- **业务规则**: 回测结果永久保存，可随时查看

#### FR-4.6 回测结果对比

- **描述**: 选择多个回测结果进行对比
- **输入**: 多个回测结果 ID（最多 5 个）
- **输出**: 对比表格和叠加的权益曲线图

### 4.5 交易执行模块

#### FR-5.1 手动下单

- **描述**: 用户通过交易界面手动提交订单
- **输入**:
  - `symbol`: 标的代码（必填）
  - `market`: 市场（必填）
  - `side`: 买卖方向（buy / sell，必填）
  - `order_type`: 订单类型（market / limit / stop，必填）
  - `qty`: 数量（必填）
  - `price`: 价格（limit/stop 单必填）
- **处理逻辑**:
  1. 校验参数合法性
  2. 调用风控引擎检查（见 FR-6.x）
  3. 创建订单记录（status = pending）
  4. 调用对应券商/交易所 API 下单
  5. 更新订单状态和 broker_order_id
  6. 通过 WebSocket 通知前端
- **输出**: 订单 ID 和初始状态
- **业务规则**:
  - 卖出数量不得超过当前持仓
  - A股买入数量必须为 100 的整数倍（1手 = 100股）
  - 加密货币数量精度由交易所规则决定
  - 下单前检查市场是否处于交易时段

#### FR-5.2 策略自动下单

- **描述**: 运行中的策略通过 `buy()`/`sell()` 方法自动下单
- **处理逻辑**: 与手动下单相同，额外关联 strategy_id
- **业务规则**:
  - 策略下单需经过风控检查
  - 策略产生的订单会记录到策略日志中

#### FR-5.3 撤单

- **描述**: 撤销一个未完全成交的订单
- **前置条件**: 订单状态为 `pending` 或 `partial_filled`
- **处理逻辑**:
  1. 调用券商/交易所撤单 API
  2. 更新订单状态为 `cancelled`
  3. 如有部分成交，更新持仓记录
- **输出**: 撤单结果（成功/失败）

#### FR-5.4 订单状态同步

- **描述**: 实时同步券商/交易所的订单状态变更
- **处理逻辑**:
  1. 通过 WebSocket 或轮询接收券商的订单状态推送
  2. 更新本地订单记录（status、filled_qty、filled_price）
  3. 订单完全成交后更新持仓记录
  4. 通过 WebSocket 通知前端
- **订单状态流转**:

```
pending → partial_filled → filled
pending → cancelled
pending → rejected
partial_filled → cancelled
```

#### FR-5.5 持仓查询

- **描述**: 查询当前用户的持仓信息
- **输出**: 持仓列表（标的、市场、策略、数量、均价、当前价格、浮动盈亏、盈亏百分比）
- **业务规则**:
  - 浮动盈亏 = (当前价格 - 持仓均价) × 持仓数量
  - 当前价格实时更新

#### FR-5.6 订单历史查询

- **描述**: 查询历史订单记录
- **输入**: 时间范围、市场、标的、策略、状态筛选、分页参数
- **输出**: 订单列表（时间、标的、方向、类型、数量、价格、状态、成交信息）

#### FR-5.7 模拟盘模式

- **描述**: 使用模拟资金进行交易，不连接真实交易所
- **处理逻辑**:
  1. 使用虚拟初始资金
  2. 订单由本地模拟撮合引擎处理
  3. 撮合价格使用实时行情的最新价
  4. 计算虚拟手续费
- **业务规则**:
  - 模拟盘与实盘使用相同的风控规则
  - 模拟盘数据独立存储，不影响实盘数据
  - 用户可在系统设置中切换模拟盘/实盘模式

### 4.6 风险管理模块

#### FR-6.1 风控规则管理

- **描述**: 用户创建和管理风控规则
- **支持的规则类型**:

| 规则类型 | 说明 | 参数 |
|----------|------|------|
| `max_position_value` | 单标的最大持仓金额 | `symbol`, `max_value` (float) |
| `max_position_ratio` | 单标的最大仓位占比 | `max_ratio` (float, 0-1) |
| `max_total_position` | 总仓位上限 | `max_ratio` (float, 0-1) |
| `stop_loss` | 单笔止损 | `symbol`, `stop_loss_pct` (float, 0-1) |
| `take_profit` | 单笔止盈 | `symbol`, `take_profit_pct` (float, 0-1) |
| `daily_loss_limit` | 日亏损限额 | `max_daily_loss` (float) |
| `daily_trade_limit` | 日交易次数上限 | `max_trades` (int) |
| `blacklist` | 禁止交易标的 | `symbols` (list[str]) |
| `max_order_amount` | 单笔最大下单金额 | `max_amount` (float) |

- **业务规则**:
  - 规则可绑定到具体策略（strategy_id 不为空），也可设为全局规则（strategy_id 为空）
  - 每个策略最多配置 20 条规则
  - 规则可随时启用/禁用

#### FR-6.2 下单前风控检查

- **描述**: 每笔订单提交前进行风控校验
- **处理逻辑**:
  1. 按优先级加载全局规则 → 策略规则
  2. 逐条检查所有启用的规则
  3. 任一规则触发则拦截订单
  4. 记录拦截日志和告警
- **输出**: 通过 / 拦截（附带具体原因）

#### FR-6.3 实时持仓监控

- **描述**: 实时监控持仓的盈亏状态，触发止损止盈
- **处理逻辑**:
  1. 每次行情更新时计算每个持仓的浮动盈亏
  2. 检查是否触发止损/止盈规则
  3. 触发时自动生成平仓订单
  4. 发送告警通知
- **业务规则**:
  - 止损止盈订单为市价单，确保快速成交
  - 自动止损不可被跳过

#### FR-6.4 日亏损限额监控

- **描述**: 监控当日累计亏损，达到限额时停止所有交易
- **处理逻辑**:
  1. 每日开盘时重置累计亏损计数
  2. 每笔平仓交易更新当日累计亏损
  3. 达到限额时：
     - 停止所有运行中的策略
     - 拒绝所有新订单
     - 发送告警通知
  4. 次日自动恢复（或管理员手动恢复）

#### FR-6.5 告警通知

- **描述**: 风控触发时向用户发送通知
- **通知渠道**:
  - 站内通知（WebSocket 推送到前端，持久化到 alerts 表）
  - 邮件通知（可选，需配置 SMTP）
  - Webhook（可选，POST JSON 到用户配置的 URL）
- **告警级别**:
  - `info`: 信息性通知（如策略启动/停止）
  - `warning`: 警告（如接近止损线）
  - `error`: 严重告警（如触发止损、达到日亏损限额）
- **业务规则**: 告警保留 90 天

## 8. 安全需求

### 8.1 认证与授权

| 需求 | 实现方式 |
|------|----------|
| 用户认证 | JWT（Access Token 30min + Refresh Token 7天） |

### 8.2 策略代码安全

| 风险 | 防护措施 |
|------|----------|
| 恶意文件操作 | 沙箱执行，禁用 `open`、`os`、`subprocess` |
| 网络访问 | 禁用 `socket`、`requests`（策略中不需要） |
| 无限循环 | 设置策略执行超时（每根K线处理 < 5 秒） |
| 内存占用 | 限制策略进程内存上限 |
| import 白名单 | 仅允许 `pandas`, `numpy`, `talib`, `math`, `datetime` 及标准库 |

### 8.3 API 安全

| 措施 | 说明 |
|------|------|
| HTTPS | 所有通信强制 HTTPS |
| CORS | 仅允许配置的前端域名 |
| Rate Limiting | 普通 API 60次/分，交易 API 10次/分 |
| Input Validation | Pydantic Schema 校验所有输入 |
| SQL Injection | ORM 参数化查询 |
| XSS | 输入转义 + CSP Header |

## 10. 约束与假设

| 编号 | 约束 |
