# 代码质量与依赖安全存量清理设计

## 背景

Quant Desk 当前功能测试和构建可以通过，但完整静态检查仍报告 358 条 Ruff 告警：主要包括长行、未使用导入、导入排序、旧式日期时区写法和旧式字符串格式化。前端生产依赖审计同时报告 4 个受影响包：`dompurify`、`echarts`、`form-data` 和受 `dompurify` 影响的 `monaco-editor`。

本轮目标是消除这些已知存量问题，而不是通过关闭规则或忽略审计结果制造表面上的“绿色”。

## 验收目标

- `ruff check app tests scripts alembic` 返回 0 告警。
- `npm audit --omit=dev` 返回 0 个生产依赖漏洞。
- 不升级 Vue、Vite、Pinia、Vue Router、Zod 等框架到新的主版本。
- 不降低 Monaco Editor 版本。
- 后端测试、前端测试、文案与布局契约、TypeScript 检查和生产构建全部通过。
- 数据库迁移链和已登录 HTTP 冒烟继续通过。
- 最终工作区干净，前后端服务保持可访问。

## 后端静态检查清理

清理分为两个阶段。

第一阶段使用 Ruff 的安全自动修复处理没有行为歧义的机械问题，包括导入排序、PEP 604 联合类型、`datetime.UTC`、缺失文件尾换行、无占位符 f-string 和可以直接转换的字符串格式化。禁止使用未审阅的 unsafe fix。

第二阶段人工处理剩余问题：

- 删除确实未使用的导入和局部变量。
- 对包级公开导出使用显式导入和 `__all__`，不依赖通配符导入。
- 对 Alembic 自动发现所需的模型导入保留明确的 `noqa: F401`，因为导入本身就是副作用契约。
- 将仅在函数内部使用的矩阵变量改为小写命名，并同步所有引用。
- 将 `AppException` 重命名为符合规则的 `AppError`，同步全仓引用，不保留产生新告警的兼容别名。
- 将 `str, Enum` 改为 Python 3.11 支持的 `StrEnum`。
- 人工折行长表达式、日志调用、模型声明和中文文案；不通过全局忽略 `E501` 达成目标。

每次语义性修改后运行相关测试。Ruff 本身就是存量问题的可重复失败用例：修复前稳定报告告警，修复后必须返回 0。

## 前端依赖安全清理

依赖升级保持在兼容范围内：

- 将 `echarts` 升级到修复 XSS 问题的 6.1.x。
- 将 `axios` 升级到当前 1.x 兼容版本，使传递依赖 `form-data` 达到已修复版本。
- 保留当前 Monaco Editor 主次版本，并在 `package.json` 使用 npm `overrides` 将传递依赖 `dompurify` 固定到审计范围之外的已修复版本。

每次依赖变更后检查 `npm ls`，确保没有无效或重复解析；随后运行 `npm audit --omit=dev`、Vitest、Vue TypeScript 构建和现有界面契约脚本。若安全版本不满足 Monaco 的依赖范围，则停止并重新评估，而不是强制安装不兼容树。

## 风险控制

- 自动修复与人工语义修复分开提交，便于审阅和回退。
- 不使用 `ruff --unsafe-fixes`。
- 不使用 `npm audit fix --force`。
- 不顺带重构业务架构或改变 API 响应。
- 删除未使用代码前先搜索全仓引用；处理包导出时增加导入烟雾验证。
- 依赖升级后必须重新构建生产包，不能只依赖审计结果。

## 验证顺序

1. 记录 Ruff 和 npm audit 的失败基线。
2. 应用安全机械修复并运行后端测试。
3. 分类别处理剩余 Ruff 告警，直到全仓归零。
4. 升级前端安全依赖并确认依赖树与 audit 归零。
5. 运行后端测试、前端测试、文案检查、布局检查和生产构建。
6. 应用 Alembic 迁移，重启前后端并验证健康检查、登录和 Setup 状态接口。

## 非目标

- 不新增业务功能或调整推荐模型逻辑。
- 不进行前端框架主版本迁移。
- 不修复与 Ruff、依赖审计无关的视觉或产品问题。
- 不启动真实的 30–60 分钟行情初始化任务。
