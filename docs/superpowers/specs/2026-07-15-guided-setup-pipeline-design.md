# Quant Desk 一键初始化与分析引导设计

## 背景

Quant Desk 的后端已经提供模型训练、模型激活和每日分析触发能力，但首次数据初始化仍只能通过命令行执行。前端看板会在没有推荐时提示“请先运行分析 Pipeline”，却没有运行入口，也无法说明数据和模型是否已准备好。

本设计补齐管理员从空数据库到生成首批推荐的完整页面流程。

## 目标

- 管理员可在看板一键启动首次初始化。
- 系统自动依次完成数据初始化、模型训练、质量门禁、模型激活和今日分析。
- 30–60 分钟的长任务进度持久化，刷新页面不丢失。
- 任务失败或后端重启后可安全继续，不重复创建业务数据。
- 系统就绪后，管理员可从看板手动运行每日分析。
- 普通用户只能查看准备和分析状态，不能触发管理操作。

## 非目标

- 不在本次工作中增加模型参数调优界面。
- 不绕过现有模型 IC 质量门禁。
- 不实现跨进程任务队列；任务仍由当前 FastAPI 进程执行。
- 不改造排名、行情、个股详情和模型管理页面的主体功能。

## 方案选择

新增独立、可持久化的 `SetupRun` 和 `SetupPipeline`，不复用每日分析的 `AnalysisRun`。

首次建库与每日分析的生命周期、阶段和错误语义不同。独立记录可以避免状态接口混杂，并为后续扩展首次配置步骤保留清晰边界。仅使用内存任务无法承受后端重启，复用 `AnalysisRun` 则会让每日运行记录包含大量一次性阶段，因此均不采用。

## 后端设计

### SetupRun 数据模型

新增 `setup_runs` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` | `String(64)` 主键 | `setup_YYYYMMDD_HHMMSS_<suffix>` |
| `status` | `String(16)` | `running`、`completed`、`failed`、`interrupted` |
| `current_stage` | `String(32)` | 当前阶段键 |
| `stages` | `JSONB` | 每阶段状态、时间、进度和错误 |
| `started_at` | 带时区时间 | 首次开始时间 |
| `finished_at` | 可空带时区时间 | 完成或失败时间 |
| `error` | 可空 `String(1024)` | 面向管理员的最终错误摘要 |
| `created_at` / `updated_at` | 带时区时间 | 复用时间戳混入 |

阶段顺序固定为：

1. `constituents`：同步沪深 300 成分股
2. `daily_bars`：逐只同步历史日线
3. `fundamentals`：同步基本面
4. `validation`：校验数据完整性
5. `training`：训练 LightGBM 模型
6. `activation`：执行 IC 门禁并激活模型
7. `analysis`：运行并等待今日分析完成

`daily_bars` 的阶段进度包含 `current`、`total`、`succeeded`、`failed` 和当前股票代码。其他阶段至少包含 `status`、`started_at`、`finished_at` 和 `error`。

### SetupPipeline 服务

新增单一职责的 `SetupPipeline`：

- 管理当前进程中的初始化任务和互斥。
- 调用现有 `DataSyncService`、`MLModelService` 和 `AnalysisPipeline`，不复制其业务算法。
- 每只股票和每个阶段完成后使用独立数据库会话更新 `SetupRun`。
- `start()` 在任务已经运行时返回现有 `run_id`，不创建第二个任务。
- 失败时停止后续阶段，记录失败阶段和原始错误摘要。
- `continue_run()` 创建新的继续任务，并根据数据库真实状态跳过已满足的步骤；历史运行记录保持不变。

为复用初始化逻辑，将 `bootstrap_data.py` 中的编排移动到服务层。命令行脚本改为调用同一个服务入口，避免页面流程和命令行流程分叉。

每日分析服务增加公开的等待式入口，使 SetupPipeline 能等待分析完成并确认当天至少生成一条预测。现有异步 `trigger()` 行为保持不变，继续供日常手动触发使用。

### 状态与操作 API

新增 `/api/v1/setup` 路由：

#### `GET /api/v1/setup/status`

所有已登录用户可访问。响应包含：

- `readiness`：`uninitialized`、`initializing`、`failed`、`ready`
- `counts`：股票、日线、模型、今日预测数量
- `active_model`：当前激活模型版本或 `null`
- `run`：最新 SetupRun 的状态、阶段和进度；从未运行时为 `null`
- `can_start`：当前用户是否为管理员且没有任务运行
- `can_run_analysis`：当前用户是否为管理员、存在激活模型且没有分析任务运行

`ready` 的判定为：存在股票和日线数据、存在激活模型，并且首次 SetupRun 已完成。今日没有预测不会把系统降级为未初始化，因为休市日或尚未运行当日分析都可能导致当天预测为空。

#### `POST /api/v1/setup/start`

仅管理员可访问。行为如下：

- 没有运行中任务时创建 SetupRun 并返回 `202` 和 `run_id`。
- 已有运行中任务时返回现有 `run_id`，不重复启动。
- 最近任务为失败或中断时，从数据库真实状态安全继续。

#### `POST /api/v1/analysis/trigger`

保留现有接口。后端增加重复运行保护：存在运行中的 AnalysisRun 时返回该运行；没有激活模型或必要数据时返回明确的 `409`，不启动空跑任务。

### 并发与重启恢复

- SetupPipeline 使用进程内锁避免同一进程重复启动，并以数据库中的 `running` 记录作为第二层保护。
- 应用启动时，将遗留的 `running` SetupRun 标记为 `interrupted`，不自动发起外部数据请求。
- 管理员点击“继续初始化”后，根据股票、日线、模型和预测的实际状态重新判断起点。
- 数据同步继续依赖现有唯一约束和 upsert 行为；重试不会插入重复股票、日线或预测。

### 质量门禁

训练完成后使用现有 `MODEL_IC_THRESHOLD` 校验并调用 `activate_model()`：

- 达标：激活新模型并继续今日分析。
- 不达标：SetupRun 在 `activation` 阶段失败，保留未激活模型和指标，页面引导管理员前往模型页查看。
- 不允许自动降低阈值或强制激活。

## 前端设计

### API 与状态管理

新增 `setupApi`，封装状态查询和启动操作。看板持有 Setup 状态，并继续使用现有 WebSocket 分析事件。初始化阶段先采用短轮询获取持久化进度；轮询只在 `readiness === "initializing"` 时开启，完成、失败或离开页面时停止。

### 系统准备状态卡

管理员在看板顶部看到以下状态：

#### 未初始化

- 标题：“完成首次配置”
- 说明：“系统将自动准备沪深 300 数据、训练模型并生成首批推荐，预计需要 30–60 分钟。”
- 主按钮：“一键初始化并生成推荐”

#### 执行中

- 展示七个阶段及完成状态。
- 日线阶段展示 `当前数量 / 总数`、成功数和失败数。
- 展示当前阶段、已用时间和最近更新时间。
- 主按钮显示“初始化中”并禁用，防止重复触发。

#### 失败或中断

- 展示失败阶段和后端返回的具体原因。
- 主按钮：“继续初始化”。
- 质量门禁失败时附加“查看模型”入口。

#### 已就绪

- 大型初始化卡收起为简洁的“系统已就绪”状态。
- 看板标题区域为管理员显示“运行今日分析”按钮。
- 分析运行时按钮显示“分析中”并禁用，继续展示现有 Analysis Pipeline 进度。

### 空状态文案

今日推荐为空时不再统一显示“请先运行分析 Pipeline”：

- 未初始化：说明需要首次配置，并提供初始化按钮。
- 初始化中：说明推荐会在流程完成后出现。
- 初始化失败：说明失败阶段，并提供继续按钮。
- 已就绪但今日未运行：提供“运行今日分析”。
- 今日分析完成但无推荐：显示“模型今日未产生符合条件的强推股票”，不把它误报为系统未运行。

普通用户看到相同状态说明，但不显示初始化、继续、训练、激活或运行分析按钮。

## 错误处理

- API 使用 `403` 表示非管理员触发管理操作。
- 每日分析前置条件不满足时使用 `409`，响应提供可直接展示的中文原因；重复触发则幂等返回当前运行，不作为错误。
- SetupPipeline 捕获阶段异常，完整错误写入服务日志，长度受控的摘要写入 SetupRun。
- 前端 toast 用于操作反馈，持久错误同时保留在状态卡中，刷新后仍可见。
- 网络轮询失败不会把任务标记为失败；页面显示连接错误并继续按退避间隔重试。
- 单只股票同步失败计入进度并继续其他股票；若最终成功率或完整性校验不满足现有要求，则在 `validation` 阶段终止。

## 测试策略

### 后端

- SetupRun 模型和迁移测试。
- readiness 判定覆盖空数据库、仅有数据、仅有未激活模型、已激活模型和已完成初始化。
- SetupPipeline 各阶段成功顺序、进度持久化和最终推荐确认。
- 成分股、行情、训练、质量门禁和分析阶段的失败传播。
- 重复触发返回同一任务，失败或中断后安全继续。
- 应用启动时将遗留运行标记为中断。
- 管理员权限和每日分析前置条件。

测试使用替身数据同步、训练和分析服务，不访问真实行情源，不训练真实模型。

### 前端

- 状态映射覆盖未初始化、执行中、失败、中断和已就绪。
- 管理员与普通用户的按钮可见性。
- 初始化触发、重复点击保护、轮询启停和错误展示。
- 空状态根据 readiness 和今日分析结果显示正确文案与操作。
- 继续运行现有登录文案、布局检查和生产构建。

## 验收标准

- 空数据库登录后，管理员能从看板一键启动完整初始化流程。
- 刷新页面后仍能看到准确阶段和日线同步进度。
- 同一时间不会启动两个初始化或每日分析任务。
- 模型未通过 IC 门禁时不会被激活，页面明确展示原因。
- 流程成功后自动生成今日排名，并切换为已就绪状态。
- 已就绪的管理员能从看板手动运行每日分析。
- 普通用户无法触发任何管理操作。
- 页面不再出现无法从当前界面执行的“请先运行 Pipeline”提示。
