# Quant Desk 个性化组合决策主路径设计

## 背景

Quant Desk 已定位为面向沪深 300 的每日股票分析与推荐平台，但当前前端仍以“看板、排名表、行情、模型、设置”五个并列模块组织产品。普通用户的选股决策、市场研究、管理员运维和个人设置混在同一层级，用户从推荐发现到执行、持仓更新和效果复盘之间也缺少完整闭环。

本设计把产品重构为面向个人投资研究者的每日组合决策工具。系统读取用户主动维护的资金、持仓和基础风险画像，在收盘后生成下一交易日可人工执行的买入、卖出和仓位调整建议。系统不连接券商下单，用户需要记录实际执行结果，系统据此更新持仓并完成后续复盘。

## 已确认的产品决策

- 首要用户是个人投资研究者，不以投研团队协作或系统管理员为主路径。
- 产品交付明确的买入、卖出和仓位建议，而不只是股票评分。
- 用户自行下单，系统不连接券商执行交易。
- 用户录入总资金、当前持仓、投资期限、风险等级和可接受最大回撤。
- 系统按真实持仓生成个性化目标权重和调仓数量。
- 建议每个交易日收盘后生成，供下一交易日执行，默认评估周期为 5 个交易日。
- 组合目标是在用户风险约束内提高风险调整后收益，而不是无约束追求绝对收益。
- 用户通过“已执行、部分执行、未执行”及实际成交价和数量反馈执行结果。
- 产品采用“每日行动中心”结构，默认首页直接呈现当天组合动作。

## 目标

- 让完成初始化的用户在进入产品后立即知道下一交易日需要执行哪些组合动作。
- 为每条建议同时提供目标仓位、数量、理由、风险、有效期和失效条件。
- 把模型信号与个性化组合建议明确区分。
- 用手工成交记录连接建议、真实持仓和复盘结果。
- 保留每日建议、执行、风险画像、模型和数据版本，确保历史结果可解释、不可被当前状态覆盖。
- 把普通用户工作区与管理员运维区域彻底分开。
- 在持仓过期、行情异常或约束无法满足时安全降级，不输出虚假精确建议。

## 非目标

- 不提供自动交易、券商下单或券商账户连接。
- 不支持融资、融券、做空、期权、期货或加密资产。
- 不支持多个投资组合或家庭账户合并管理。
- 不覆盖沪深 300 以外的股票池。
- 不提供盘中实时调仓建议。
- 不承诺未来收益或保证实际最大回撤不会超过用户填写的阈值；该阈值用于组合约束、历史情景检查和风险提示。
- 不在本次设计中完成商业化投顾业务所需的法律与合规方案；如产品面向第三方提供服务，需单独进行合规评估。

## 产品主路径

首次使用：

```text
风险画像
→ 总资金
→ 当前持仓
→ 组合约束确认
→ 数据校验
→ 生成首份建议
```

日常使用：

```text
查看今日调仓建议
→ 查看个股依据与风险
→ 用户自行下单
→ 记录实际执行
→ 更新持仓
→ 持续跟踪
→ 到期复盘
```

## 信息架构

### 普通用户主菜单

1. **今日**：当天组合状态、买入、卖出、调仓建议和风险提醒。
2. **持仓**：真实持仓、资金、盈亏、目标偏差和组合风险。
3. **选股**：模型候选池、筛选、个股研究和关注名单。
4. **市场**：沪深 300、行业表现、市场风险和组合所处环境。
5. **复盘**：历史建议、实际执行、组合收益和偏差归因。

### 管理员分组

- 分析任务
- 模型与回测
- 系统管理

管理员同时拥有普通用户路径，但管理能力不能混入普通用户主菜单。普通用户不能看到管理员页面、按钮、快捷入口或命令项。

### 个人菜单

- 投资画像与组合设置
- 通知与外观
- 账户安全
- 退出登录

### 全局顶部栏

- 当前建议交易日
- 行情、持仓和模型数据更新时间
- 全局股票搜索
- 数据异常、建议失效或持仓过期提醒

品牌统一使用 `Quant Desk`，移除 `Stock Analysis`、`Workspace` 等混合命名。

### 路由归属

- “个股详情”是今日、持仓、选股、市场和复盘共同使用的二级页面。
- 个股详情必须通过面包屑和返回目标保留入口来源，不能只调用浏览器后退。
- 旧路由在迁移期可以重定向到新路由，书签不能直接失效。

## 首次初始化

首次初始化采用分步流程，每一步都可保存并继续：

1. 投资期限和风险等级。
2. 可接受最大回撤。
3. 总资金、可用现金和当前持仓。
4. 单只股票、行业、现金和单日调仓约束。
5. 数据校验与约束确认。

必要字段完成前，用户可以浏览选股和市场，但不能生成精确目标股数。初始化结果保存后，默认进入“今日”。

## 今日页面

“今日”只回答一个核心问题：下一交易日应该如何调整当前组合。

### 今日组合摘要

展示：

- 当前总资产、现金、持仓市值和总仓位。
- 调仓后的目标总仓位和预计剩余现金。
- 当前风险等级和最大回撤约束。
- 建议日期、生成时间、有效交易日和状态。
- 行情日期、持仓更新时间和模型版本。

持仓数据超过允许时效后，页面可以展示方向性模型信号，但必须暂停目标股数计算并要求用户先更新持仓。

### 今日行动清单

行动按优先级排序：

1. 清仓
2. 减仓
3. 买入
4. 加仓
5. 继续持有

“继续持有”默认折叠。每条建议包含：

- 股票名称、代码和行业。
- 当前数量、当前权重和成本。
- 建议动作。
- 目标权重、目标数量和调整数量。
- 计算参考价格、允许偏离范围和建议有效期。
- 模型评分、排名和置信度。
- 主要正向因素和主要风险。
- 建议失效条件。
- 是否受现金、集中度或换手约束影响。

参考价格用于计算目标数量，不等于成交保证。目标数量必须遵守交易单位、可用资金和费用约束。

默认执行窗口是建议对应的下一交易日；当日收盘后未处理的行动转为过期。若盘中参考价格偏离超过建议允许范围，可以在收盘前提前失效。过期或失效建议只能记录结果，不能继续标记为新的有效成交建议。

### 建议状态

- `generating`：正在生成。
- `ready`：可以执行。
- `partially_handled`：部分建议已处理。
- `handled`：所有建议已处理。
- `expired`：超过有效期。
- `superseded`：由新版本替代。
- `failed`：当日任务失败，没有形成正式建议。

### 建议版本

- 正式建议生成后冻结保存。
- 同一用户、同一建议交易日只能有一个当前正式版本。
- 重新生成必须创建新版本，并将旧版本标记为已替代。
- 历史建议继续引用生成时的持仓、风险画像、模型和行情版本。
- 旧建议不得自动延长有效期。

## 持仓与投资画像

### 持仓总览

展示：

- 总资产、可用现金和持仓市值。
- 今日盈亏和累计盈亏。
- 当前总仓位和目标总仓位。
- 当前回撤、集中度、行业暴露和换手。
- 最近更新时间和估值价格日期。

### 持仓明细

每只股票展示：

- 股票名称、代码和行业。
- 持有数量、成本价和最新参考价。
- 市值、盈亏和当前权重。
- 系统目标权重和当前偏差。
- 当前组合建议。

用户可以手工新增、修改和删除持仓。每次修改保留修改时间、修改前数据、修改后数据和操作者。

### 资金变化

资金事件独立记录：

- 追加资金。
- 取出资金。
- 手续费和成本修正。

资金进出不能直接计入投资收益。复盘使用经过现金流调整的组合净值。

### 投资画像与组合约束

- 总资金。
- 投资期限。
- 风险等级。
- 可接受最大回撤。
- 单只股票最大权重。
- 单一行业最大比例。
- 最低现金比例。
- 单日最大调仓比例。

风险等级提供默认约束，用户只能在服务端允许的范围内调整。风险画像修改后生成新版本，只影响后续建议。

### 一致性检查

生成建议前检查：

- 持仓是否在允许时间内更新。
- 现金、持仓数量和市值是否有效。
- 是否存在未知股票、负数数量或异常成本。
- 上一份建议是否仍有未处理项目。
- 是否存在未记录的资金变化。

一致性检查失败时暂停精确仓位建议，但不阻止用户浏览研究信息。

## 选股与个股研究

### 选股页面

默认显示最新有效交易日的沪深 300 候选池，并支持查看历史交易日。

核心字段：

- 排名、股票和行业。
- 模型评分、置信度和标签。
- 较上一有效交易日的排名和标签变化。
- 主要正向因素和风险摘要。
- 当前是否持有及当前权重。
- 是否在今日行动清单。
- 当前组合建议。
- 是否在关注名单。

支持按日期、行业、标签、评分、置信度、持仓状态和关注状态筛选。

页面必须区分：

- **模型信号**：股票本身的相对吸引力。
- **组合建议**：结合用户持仓、现金、相关性和风险约束后的实际动作。

高评分股票可以因为行业过度集中、现金不足、换手限制或风险过高而显示“暂不买入”。

### 个股详情

统一包含：

1. 当前行情、数据日期和数据状态。
2. 模型评分、排名、标签和历史变化。
3. 用户持仓、成本、当前权重和组合建议。
4. 看好理由、风险因素和建议失效条件。
5. K 线、成交量、基本面和资金数据。
6. 历史建议、执行和后续表现。

历史表现至少包含建议后 1、3、5、10 个交易日结果。用户可以从详情页加入关注或处理对应建议。

## 市场页面

“市场”聚焦沪深 300，不再提供美股和加密货币入口。

展示：

- 沪深 300 指数和当日状态。
- 上涨、下跌和平盘数量。
- 成交额、波动水平和市场风险状态。
- 行业涨跌和强弱分布。
- 用户持仓和候选股票所在行业的表现。
- 关注股票和持仓股票的简要行情。

股票搜索和 K 线保留为辅助功能，不占据页面主体。行情数据必须显示来源日期和更新时间；请求一次的价格不能标记为“实时监控”。

## 人工执行记录

每条建议支持：

- 全部执行。
- 部分执行。
- 未执行。
- 过期未处理。

执行表单记录：

- 实际成交数量。
- 实际成交价格。
- 成交时间。
- 手续费。
- 未执行或部分执行原因。

保存时校验：

- 卖出数量不能超过可卖持仓。
- 买入资金与费用不能超过可用现金。
- 数量和价格必须为有效正数。
- 同一执行记录的重复提交必须保持幂等。

保存成功后以实际成交更新现金和持仓，并保留成交前后的组合快照。用户可以修正误录记录，但修正必须产生审计记录，不能直接覆盖历史。

## 复盘页面

复盘区分模型质量、组合约束和用户执行三类影响。

### 组合表现

- 组合净值与沪深 300 对比。
- 累计收益和年化收益。
- 最大回撤和波动率。
- 风险调整后收益。
- 按日、周、月查看表现。

### 建议表现

- 买入建议后 1、3、5、10 个交易日表现。
- 减仓或清仓后对应区间表现。
- 不同标签、行业和置信度的结果。
- 建议触发、失效、过期和处理数量。
- 模型理论组合表现。

### 执行偏差

- 建议价格与实际成交价格差异。
- 建议数量与实际数量差异。
- 建议时间与实际执行时间差异。
- 未执行、部分执行和延迟执行。
- 因执行偏差产生的结果差异。

最终归因结构为：

```text
实际组合结果
= 模型信号贡献
+ 组合约束影响
+ 用户执行偏差
+ 建议生成后的市场变化
```

归因是解释性分析，不应伪装为严格因果证明。

### 数据不足状态

数据不足必须说明原因：

- 尚未积累足够交易日。
- 用户未填写实际成交。
- 行情数据缺失。
- 建议尚未到评估期限。

无数据不能显示为 0% 收益或 0% 命中率。

## 组合建议引擎

### 输入

- 最新正式模型对沪深 300 的股票信号。
- 最近有效行情和风险估计数据。
- 用户最新现金和持仓。
- 当前风险画像与组合约束。
- 交易成本和换手约束。

### 目标

在约束范围内提高预期风险调整后收益，同时控制集中度、换手、现金占用和历史情景风险。

可采用“预期收益信号减去风险惩罚与交易成本”的优化目标。具体算法在实施计划中确定，但必须满足以下产品约束：

- 不允许空头权重。
- 总权重不能超过可投资资产。
- 保留用户要求的最低现金比例。
- 单股和行业权重不能超过限制。
- 单日建议换手不能超过限制。
- 无可行解时降低风险和仓位，而不是放宽用户约束。

用户填写的最大回撤用于历史情景和压力检查，不能作为未来回撤保证。页面文案不得表达“保证不超过最大回撤”。

## 每日数据流

```text
收盘行情同步
→ 数据完整性检查
→ 模型生成股票信号
→ 读取用户最新持仓与风险画像
→ 生成目标组合
→ 风险和交易约束校验
→ 冻结每日建议
→ 发送业务通知
→ 用户次日人工执行
→ 记录实际成交
→ 更新现金和持仓
→ 生成组合快照
→ 到期后计算复盘结果
```

每日任务按交易日和用户保持幂等。单个用户数据异常不能阻塞其他用户建议生成。

## 后端领域边界

### 投资画像

负责用户风险参数及其版本。其他模块只读取已生效版本，不直接修改画像。

### 组合与持仓

负责现金、持仓、资金事件和每日快照。建议模块不直接修改持仓，只有执行记录和人工修正可以产生持仓变更。

### 每日建议

负责建议头、建议明细、目标权重、行动、理由、风险、有效期和版本状态。正式建议不可变。

### 执行记录

负责用户对建议的处理结果、实际成交和幂等更新。保存成功后通过组合领域更新持仓。

### 复盘评估

只读取历史快照、建议、成交和行情，生成可重算的评估结果，不修改源记录。

现有市场、模型、排名和个股能力通过明确接口为上述领域提供数据。

## 管理员功能

### 分析任务

- 数据同步、特征计算、模型预测和建议生成进度。
- 最近成功日期、失败原因、重试和恢复。
- 下次计划执行时间。
- 数据完整性和数据源状态。

普通用户只看到“生成中、可用、异常”等结果状态，不暴露内部 Pipeline。

### 模型与回测

- 模型版本、训练区间和参数。
- IC、稳定性、回撤和分组收益。
- 版本横向比较。
- 异步训练和回测进度。
- 激活前确认、激活历史和回滚。

新模型不得仅因达到阈值自动覆盖生产模型，必须通过明确激活操作生效。

### 系统管理

- 股票池和每日分析计划。
- 数据保留和清理策略。
- 用户、角色和账户状态。
- 审计日志。
- 通知发送记录。
- 系统异常和数据源状态。

## 通知

用户可选择接收：

- 今日建议已生成。
- 建议即将失效。
- 持仓需要更新。
- 风险约束被触发。
- 数据或模型异常。

邮件和 Webhook 是发送渠道，业务事件是订阅对象。通知记录必须保存事件、渠道、发送时间、状态和失败原因。

## 权限、隐私与审计

- 所有组合、持仓、执行和投资画像数据按用户隔离。
- 普通用户只能访问自己的组合数据。
- 管理员页面、快捷入口和写操作统一使用服务端权限校验。
- 管理员不能通过普通业务接口修改用户的执行历史。
- 持仓、画像、建议、执行和管理员操作记录审计信息。
- API、日志和通知响应不能暴露密码、Webhook 密钥或不必要的持仓明细。
- 产品不自动读取券商账户，不自动发送交易指令。

## 全局页面状态规范

所有主页面必须区分：

- 初次加载。
- 加载失败。
- 无业务数据。
- 数据过期。
- 后台任务运行中。
- 可操作。
- 操作处理中。
- 操作成功。
- 业务校验失败。

加载失败不能显示成“暂无数据”；任务失败不能显示成“尚未生成”；过期建议不能显示成可执行建议。每个错误状态需要提供明确原因和可行下一步。

## 测试策略

### 单元测试

- 风险画像和组合约束验证。
- 目标权重、数量取整、现金和费用计算。
- 无可行解时的降仓行为。
- 资金进出与组合净值计算。
- 部分执行、未执行和执行偏差计算。
- 建议有效期和状态转换。

### API 与领域测试

- 用户数据隔离和管理员权限。
- 建议冻结、版本替代和幂等性。
- 执行记录对现金和持仓的原子更新。
- 重复提交不会重复扣款或更新持仓。
- 风险画像版本只影响后续建议。
- 复盘重算不修改源数据。

### 页面测试

- 首次初始化步骤和恢复。
- 今日页面全部建议状态。
- 持仓过期时暂停精确建议。
- 模型信号与组合建议分开展示。
- 执行表单的资金、持仓和数量校验。
- 空、错误、过期、加载和完成状态。
- 普通用户不渲染管理员菜单和操作。

### 端到端测试

覆盖完整路径：

```text
创建投资画像和初始持仓
→ 生成每日建议
→ 查看个股依据
→ 部分执行买入建议
→ 跳过一条建议
→ 更新持仓与现金
→ 建议到期
→ 查看组合和执行偏差复盘
```

同时覆盖非交易日、停牌、行情缺失、持仓过期、建议价格失效和后台任务失败。

## 验收标准

- 完成初始化的用户登录后默认进入“今日”。
- 用户能在一个页面看清所有需要执行的组合动作及其优先级。
- 每条可执行建议都包含目标权重、目标数量、参考价格、有效期、理由、风险和失效条件。
- 持仓过期或数据异常时不会生成虚假精确数量。
- 用户能记录全部执行、部分执行和未执行，并看到现金与持仓正确更新。
- 用户能从今日、持仓、选股、市场和复盘进入统一个股详情并返回原上下文。
- 复盘能区分模型表现、组合约束和执行偏差。
- 历史建议、画像、模型和执行数据不会被当前设置覆盖。
- 普通用户看不到管理员页面或操作；管理员能力集中在独立分组。
- 所有主页面正确区分加载、空、错误、过期和任务状态。
- 产品所有可见品牌统一为 `Quant Desk`。

## 分阶段交付建议

### 第一阶段：组合基础与每日行动

- 新导航和角色分组。
- 首次投资画像与持仓初始化。
- 持仓、现金和资金事件。
- 每日建议模型、版本和今日页面。
- 人工执行记录和持仓更新。

### 第二阶段：研究链路

- 选股页面重构。
- 个股详情补齐模型历史、持仓建议和建议后表现。
- 市场页面重构为沪深 300 市场环境。
- 关注名单与全局搜索。

### 第三阶段：复盘与可信度

- 组合快照和净值。
- 建议到期评估。
- 执行偏差与结果归因。
- 历史建议和复盘页面。

### 第四阶段：管理员与运营完善

- 分析任务中心。
- 模型比较、异步回测、激活和回滚。
- 用户与审计页面。
- 业务通知订阅和发送记录。

每个阶段都必须保持前一阶段主路径可用，不以尚未完成的后续模块作为当前流程的必要依赖。

## 实施规格拆分

本文档是主路径和信息架构总纲，不对应一次性实施全部四个阶段。

- 首个实施计划只覆盖第一阶段“组合基础与每日行动”。
- 第二阶段开始前，单独确认选股、个股、市场和关注名单的详细交互与接口规格。
- 第三阶段开始前，单独确认净值、基准、评估期限和归因计算规格。
- 第四阶段开始前，单独确认管理员任务、模型生命周期、用户管理和通知运营规格。

后续阶段可以复用本文档的边界和术语，但不能在未完成对应设计确认前直接扩大当前实施范围。
