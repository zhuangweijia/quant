## Context

当前系统是一个完整的多市场量化交易平台（A股 / 美股 / 加密货币），包含行情采集、策略引擎、回测、交易执行、风控、看板等模块。代码量约 60% 集中在交易域（broker 适配、订单管理、持仓、风控、Account）。在单用户自用场景下，交易执行链路是复杂度最高、价值最低的部分。

系统已有可复用的基础设施：FastAPI 骨架、async SQLAlchemy + PostgreSQL、Redis 缓存、APScheduler 定时任务、WebSocket 推送、Vue 3 前端、Docker 部署、AKShare A 股数据集成。

本次转型将系统重构为 A 股 AI 选股分析平台：砍掉交易域，保留数据层和基础设施，新增 ML 选股引擎和每日排名能力。

## Goals / Non-Goals

**Goals:**

- 每日收盘后自动运行分析 Pipeline，产出沪深 300 全部股票的评分排名
- 使用 LightGBM 跨截面收益预测模型，自动学习因子权重（用户无需理解技术指标）
- 输出每日排名表（强推 / 观望 / 回避分档）+ 个股 SHAP 解释（大白话）
- 支持模型历史回测验证（按排名分组能否跑赢沪深 300）
- 首次部署可在一小时内完成沪深 300 历史数据拉取
- 复用现有 80% 基础设施代码（认证、Redis、PostgreSQL、Docker、WebSocket、前端壳）

**Non-Goals:**

- 实时选股推荐（本版仅每日批量）
- 港股支持（v2）
- 全 A 股 5000 只覆盖（v2，本版仅沪深 300）
- 多用户 / SaaS 化（纯自用）
- 自动交易执行（不做交易）
- LLM 研报分析 / 舆情分析（v2 候选）
- 端到端深度学习模型（LSTM / Transformer，复杂度过高且易过拟合）

## Decisions

### Decision 1: LightGBM 而非深度学习

**选择**: 使用 LightGBM（梯度提升树）作为选股模型。

**理由**:
- 金融数据信噪比极低，树模型对小样本 + 高噪声数据的鲁棒性远优于神经网络
- 表格数据（因子矩阵）是 LightGBM 的主场
- 训练快（CPU 秒级），无需 GPU
- SHAP 原生支持，解释性好
- 量化基金行业标配，验证充分

**备选方案**:
- LSTM / Transformer: 更适合时序，但金融时序噪声大、易过拟合、需大量调参、训练慢、SHAP 不直接。放弃。
- 线性回归（IC 加权因子模型）: 透明但无法捕捉因子间非线性交互。可作为 baseline 对比，不作为主力。

### Decision 2: 沪深 300 作为初始股票池

**选择**: v1 股票池为沪深 300 成分股。

**理由**:
- 300 只 vs 全 A 股 5000 只，历史数据拉取量降低 17 倍，首次部署从天级降到小时级
- 沪深 300 覆盖约 50% 总市值，是个人投资者实际会考虑的标的池
- 流动性好，数据质量高，减少停牌 / 退市 / ST 的噪声干扰
- 可在 v2 平滑扩展到中证 500 或全 A 股

**备选方案**:
- 全 A 股: 数据量和模型训练成本过高，v1 不值得。放弃。
- 中证 500: 流动性不如沪深 300，且数量介于两者间没有明显优势。v2 可叠加。

### Decision 3: 特征工程 — 系统自动计算 6 大类因子

**选择**: 系统内置因子库，自动计算，用户无需理解或配置。

**因子分类与具体因子（v1 约 40-50 个）**:

| 类别 | 因子 | 说明 |
|------|------|------|
| 动量 (Momentum) | 5/10/20/60 日收益率、相对沪深300超额收益、12月动量去掉最近1月 | 价格趋势强度 |
| 估值 (Value) | PE/PB/PS TTM、股息率、行业估值分位数 | 便宜程度 |
| 质量 (Quality) | ROE TTM、毛利率、资产负债率、经营现金流/净利润 | 公司基本面健康度 |
| 成长 (Growth) | 营收同比增速、净利润同比增速、营收环比增速 | 业绩增长 |
| 量价 (Volume-Price) | 换手率、20日波动率、量价相关系数、成交量比率 | 交易活跃度和异常 |
| 资金流 (Flow) | 北向资金持股比例变化、主力净流入率 | 聪明钱动向 |
| 技术 (Technical) | RSI、MACD信号、布林带位置、均线多头排列评分 | 技术形态 |

**理由**:
- 用户明确表示不懂技术指标，因子计算必须完全自动化
- 6 大类覆盖了主流量化选股的因子空间
- LightGBM 会自动学习哪些因子重要、权重多少——这就是"AI 发现规律"
- 因子库可后续扩展，不影响模型架构

### Decision 4: 标签设计 — 未来 5 日相对收益分档

**选择**: 标签为未来 5 个交易日的相对收益（个股收益 - 沪深 300 收益），离散化为 3 档（0=跑输, 1=持平, 2=跑赢）。

**理由**:
- 5 日窗口平衡了信号强度和持仓节奏（个人投资者不太可能每天调仓）
- 相对收益（超额收益）去除了市场 beta，让模型专注选股 alpha
- 离散化（分类）比回归更鲁棒，金融连续值预测噪声太大
- 3 档避免了二分类的粗暴，也避免了 5/10 档的过拟合风险

**备选方案**:
- 未来 1 日收益: 噪声过大，IC 极低
- 未来 20 日收益: 信号更强但持仓周期太长，不适合个人投资者
- 连续回归: 噪声太大，模型不稳定

### Decision 5: SHAP 解释 + 大白话翻译

**选择**: 使用 SHAP (TreeExplainer) 计算每只股票的因子贡献，前端展示 Top 3 正向 / 负向因素，用自然语言模板翻译。

**理由**:
- 用户不懂技术指标，不能直接展示"RSI=72"或"PE_TTM=22.3"
- SHAP 是树模型解释的事实标准，精确且高效
- 自然语言模板将因子贡献翻译为"近期动量强劲 (+0.31)" / "估值低于行业均值 (+0.24)"
- 保持透明但不要求用户理解计算细节

### Decision 6: Pipeline 编排 — 复用 APScheduler

**选择**: 复用现有 strategy_engine.py 中的 APScheduler 基建，重构为 AnalysisPipeline 调度器。

**理由**:
- 现有代码已有 AsyncIOScheduler + CronTrigger 成熟模式
- Pipeline 本质是定时任务（每日收盘后），APScheduler 完美匹配
- 无需引入 Airflow / Celery 等重型编排框架

### Decision 7: 数据存储 — 日 K 缓存到 PostgreSQL

**选择**: 将沪深 300 的历史日 K 线和基本面数据缓存到 PostgreSQL（daily_bar 表），而非每次实时调用 AKShare。

**理由**:
- AKShare 非官方，频繁调用有限频和 break 风险
- 模型训练需要反复读取历史数据，从 DB 读比每次从 AKShare 拉快几个数量级
- PostgreSQL 已有，无新依赖
- 增量同步：每日只拉最新一天的数据

### Decision 8: 模型版本管理 — 文件 + DB 元数据

**选择**: 模型文件存储在 `backend/models/` 目录（.txt 格式 LightGBM），DB 记录版本元数据（训练时间、数据范围、IC、特征重要性）。

**理由**:
- LightGBM 模型文件小（KB 级），无需 MLflow 等重型工具
- DB 元数据支持版本对比和回滚
- 简单、够用、符合自用场景

## Risks / Trade-offs

**[AKShare 限频 / 改版 break]** → 增量同步机制 + 断点续传 + 错误重试 + 数据完整性校验；首次全量拉取设计为可重入（已拉取的股票跳过）；监控 AKShare 调用失败率，超阈值告警

**[ML 过拟合 — 模型在历史数据上表现好但实盘失效]** → 使用 walk-forward / 滚动窗口验证（而非简单 train/test split）；保留 out-of-sample 测试集；模型验证模块强制要求回测通过后才部署；模型 IC 低于阈值时不输出排名（输出"模型信号弱，今日无推荐"）

**[金融数据低信噪比 — IC 可能仅 0.03-0.05]** → 设定合理预期：模型提供统计边际而非水晶球；排名分档而非精确预测；长期累积视角而非单次押注

**[删除交易域是大范围 BREAKING 变更]** → 分阶段迁移：先新增分析模块（不动旧代码），再删除旧模块；数据库迁移提供 downgrade；保留 git 历史以便回溯

**[沪深 300 成分股变动]** → 定期同步沪深 300 成分股列表（每月）；历史数据保留已退出成分股的记录（不删除）；模型训练时按当时成分股筛选，避免幸存者偏差

**[基本面数据获取复杂]** → AKShare 的财务数据 API 杂乱且字段不统一，需封装一层统一的财务数据适配器；优先获取最核心的指标（PE/PB/ROE/营收增速），降低数据复杂度
